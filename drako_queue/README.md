# Continuous admitted ticket queue

An active native lane owns the existing fixed drako-map summary/test paths. Per-ticket result means independently VERIFIED_ACTIVE, not controller finish or owner acceptance. After native process-group exit, host verifies exact owner/revision/scopes/output and publishes each ticket's PR, trace/eval and Plane evidence. Only then does it prepare and launch the next admitted ticket through supported agent-resume-task. The same logical client/profile/session and claim persist; only the new receipt scope is extended. The ownership controller, approvals and permissions are unchanged.

`entry.py --project <admitted map worktree> init --config <private config> --ticket A --ticket B --branch feat/a --branch feat/b` admits exactly two selected real tickets. `run <queue-dir>` performs both automatically. PR B stacks on PR A's branch; neither is merged. Result snapshots and exact source heads preserve ticket A after ticket B advances the worktree. A drained queue remains ACTIVE and quiescent, not finished/released; this narrow reservation intentionally blocks competing writers. `init ... --continue-from <idle-queue-dir>` admits a new bounded successor using that same active owner after exit/revision checks; prior admissions remain immutable. One successor per parent.

Foreign/live/terminal/unknown ownership, changed admitted tickets/source, uncertain native/prepare/commit/PR outcomes and exhausted limits hold. No SQL writes, owner_accept, force unlock or implicit sealed-claim adoption. Existing sealed legacy reservation may need one initial owner release before a new continuous lane starts; approvals are not needed between its admitted tickets. Old jobs and commands remain unchanged. Lane termination/release is separate, never fabricated by machine verification.

Gate: Python3.14 `-B -m unittest discover -s drako_queue -p test_queue.py -v`, existing recovery/profile boundary gates, then two actual native real-project tickets and independent controller/API/Git/trace/eval readback. Production map canonical typecheck/build/test/lint and immutable acceptance remain required for every ticket. Queue and per-ticket execution/verification budgets do not reset on recovery. No arbitrary project/command selection or automatic merge/deployment.
